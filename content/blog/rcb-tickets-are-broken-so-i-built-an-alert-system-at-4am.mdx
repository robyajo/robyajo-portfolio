Building high-frequency monitoring systems for web services often reveals a tough architectural tradeoff: cloud API rate limits and token costs quickly erode margins when running continuous polling loop tasks.

When designing event-driven automation for city-scale municipal platforms and real-time alerts, I needed an architecture that could analyze raw data payloads continuously with zero per-request fee structure.

I'm <TypographyMark>Roby Karti S.</TypographyMark>, a fullstack developer building digital services in Pekanbaru, Indonesia. In this post, I detail how running quantized open-source AI models alongside lightweight event-driven TypeScript loops creates high-throughput, low-latency alerting systems.

## The Challenge: Real-Time Event Processing at Scale

When polling third-party endpoints or monitoring public service databases for real-time status updates, standard scraping methods encounter several roadblocks:

1. **Anti-Bot and Rate Limits**: Rapid HTTP requests trigger IP blocks or Cloudflare challenge pages if request headers are unhandled.
2. **Dynamic DOM and Payload Structures**: Traditional CSS selector parsers break whenever the target application updates its frontend build artifacts.
3. **High Operational Overhead**: Sending thousands of raw DOM or JSON payloads to proprietary cloud LLMs for content parsing incurs unsustainable API fees.

<TypographyMark>
    The solution lies in decoupling data ingestion from intelligence parsing
    using lightweight local AI models running on edge nodes.
</TypographyMark>

## System Architecture: Event Polling + Local AI Intelligence

The automated pipeline operates on a concurrent two-phase architecture:

1. **Ingestion Fiber**: An asynchronous polling service with dynamic jitter and exponential backoff fetching structured data payloads.
2. **Local AI Parsing Fiber**: A local open model (such as `qwen2.5-coder:3b` or `llama3.2:3b`) running via local inference engine, evaluating changes and classifying anomalies in under <TypographyMark>25 milliseconds</TypographyMark>.

```
└──────────────────┘      └─────────────────────┘      └─────────────────────┘
```

## Implementing a Dynamic Concurrent Polling Engine

To prevent thundering herd problems and manage rate limits safely, the polling engine uses adaptive dynamic delays and cryptographic payload hashing:

```typescript
import crypto from "node:crypto";

interface ServiceState {
    lastHash: string;
    failCount: number;
    isHealthy: boolean;
}

export class ServiceMonitor {
    private state: ServiceState = {
        lastHash: "",
        failCount: 0,
        isHealthy: true,
    };
    private baseDelayMs = 2000;
    private maxDelayMs = 30000;

    // Compute SHA-256 hash to detect changes before invoking AI parser
    private calculateHash(payload: string): string {
        return crypto.createHash("sha256").update(payload).digest("hex");
    }

    // Calculate dynamic jitter delay to avoid uniform request spikes
    private getNextDelay(): number {
        if (this.state.failCount > 0) {
            const backoff =
                this.baseDelayMs * Math.pow(2, this.state.failCount);
            return Math.min(backoff, this.maxDelayMs);
        }
        // Add random 10-30% jitter to normal poll intervals
        const jitter = Math.random() * 0.3 * this.baseDelayMs;
        return this.baseDelayMs + jitter;
    }

    public async evaluatePayload(rawPayload: string): Promise<boolean> {
        const currentHash = this.calculateHash(rawPayload);

        if (currentHash === this.state.lastHash) {
            // Content unchanged - bypass heavy processing
            return false;
        }

        this.state.lastHash = currentHash;
        return true; // Flag for local AI classification
    }
}
```

## Classification with Local Quantized AI Models

When payload changes are detected, the system passes the delta to a local 3B-parameter open model over a unix socket or HTTP localhost interface.

Using Ollama's local JSON-structured output mode, the model evaluates state without network hops:

```typescript
export async function classifySystemEvent(eventData: string) {
    const response = await fetch("http://127.0.0.1:11434/api/generate", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
            model: "qwen2.5-coder:3b",
            prompt: `Analyze this system status update and extract key status indicators as JSON:\n${eventData}`,
            format: "json",
            stream: false,
        }),
    });

    const result = await response.json();
    return JSON.parse(result.response);
}
```

Because the model runs locally, processing 100,000 payload checks costs <TypographyMark>$0.00 in cloud fees</TypographyMark> while keeping response latency consistently below 30ms.

## Key Takeaways

Combining open-source quantized AI models with solid backend engineering principles unlocks a new class of resilient microservices:

1. **Filter Early**: Use fast cryptographic hashes (SHA-256) to filter out unchanged data before invoking LLM inference.
2. **Execute Locally**: Quantized 3B to 7B models excel at structured classification, running fast on standard hardware.
3. **Decouple Alerts**: Webhooks and notification dispatchers (Telegram, Discord, SMS) should run on separate queue fibers so alert delivery never blocks ingestion loops.

By building on open-weights foundation models, developers can create real-time, privacy-first automation that runs reliably for years without cloud vendor lock-in.
