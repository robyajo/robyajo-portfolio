Building effective AI integrations requires moving beyond basic text generation. When software systems need artificial intelligence to read database tables, query Git repositories, or interact with municipal service APIs, unstructured prompt chains quickly break down.

To make AI systems reliable in production, we must treat tools, context, and capabilities as **machine-readable protocols**.

In this post, I explore how open standards like the [Model Context Protocol (MCP)](https://modelcontextprotocol.io/) and structured schema designs enable AI agents to execute complex, multi-step engineering tasks safely.

## The Problem with Proprietary Tool Integration

Historically, connecting a language model to external software required writing custom function-calling wrappers for every specific API or model vendor. This approach created three distinct challenges:

1. **Vendor Lock-In**: Tool definitions formatted for one LLM provider could not be reused across open-source local models without complete rewrite layers.
2. **Brittle Context Injection**: Passing arbitrary file contents or state dumps into system prompts wasted context window tokens and increased hallucination rates.
3. **Security and Permission Risks**: Giving an AI agent direct database or shell execution capabilities without standardized permission boundaries created severe security vulnerabilities.

The solution is a universal, open standard that decouples model inference from system tools and data sources.

## Understanding the Model Context Protocol (MCP)

The Model Context Protocol (MCP) is an open-source architecture that standardizes how applications provide context and tools to AI models. Much like how Language Server Protocol (LSP) standardized code editor auto-completion, MCP provides a uniform interface between AI clients and local or remote data servers.

<TypographyMark>
    MCP transforms raw model capabilities into deterministic, structured
    client-server interactions.
</TypographyMark>

```
┌─────────────────────────┐                ┌─────────────────────────┐
│     MCP Host / Client   │                │        MCP Server       │
│  (Zed / VS Code / App)  │ ◄── JSON-RPC ──► (Database / Git / API)  │
└────────────┬────────────┘                └─────────────────────────┘
             │
             ▼
┌─────────────────────────┐
│     AI Model / LLM      │
└─────────────────────────┘
```

An MCP implementation exposes three primitive capabilities:

- **Resources**: Readable, context-rich data sources (e.g., file contents, system logs, API endpoints).
- **Tools**: Executable functions that perform side-effect actions (e.g., executing SQL queries, pushing Git commits, updating database records).
- **Prompts**: Parameterized, pre-tested prompt templates designed for specific operational workflows.

## Implementing a Type-Safe MCP Server in TypeScript

To demonstrate how open agent protocols function in practice, here is a lightweight MCP server implementation built in TypeScript that exposes structured database diagnostics to local AI clients.

```typescript
import { Server } from "@modelcontextprotocol/sdk/server/index.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import {
    CallToolRequestSchema,
    ListToolsRequestSchema,
} from "@modelcontextprotocol/sdk/types.js";
import { z } from "zod";

const server = new Server(
    {
        name: "system-health-mcp",
        version: "1.0.0",
    },
    {
        capabilities: {
            tools: {},
        },
    },
);

// Register available tools for AI agents
server.setRequestHandler(ListToolsRequestSchema, async () => ({
    tools: [
        {
            name: "query_service_status",
            description:
                "Get real-time operational status and metrics for a specific system service.",
            inputSchema: {
                type: "object",
                properties: {
                    serviceName: {
                        type: "string",
                        description:
                            "Name of the service (e.g., postgres, redis, api)",
                    },
                },
                required: ["serviceName"],
            },
        },
    ],
}));

// Handle tool execution requests deterministically
server.setRequestHandler(CallToolRequestSchema, async (request) => {
    if (request.params.name === "query_service_status") {
        const serviceName = String(request.params.arguments?.serviceName);

        // Perform deterministic system lookup
        const statusReport = {
            service: serviceName,
            status: "healthy",
            latencyMs: 12,
            activeConnections: 42,
            timestamp: new Date().toISOString(),
        };

        return {
            content: [
                {
                    type: "text",
                    text: JSON.stringify(statusReport, null, 2),
                },
            ],
        };
    }

    throw new Error(`Tool not found: ${request.params.name}`);
});

// Start transport channel over standard I/O
const transport = new StdioServerTransport();
await server.connect(transport);
```

By enforcing strict JSON-RPC communications, the host application inspects, logs, and validates every tool call before permitting execution.

## Key Architectural Advantages

Adopting open, machine-readable protocols delivers tangible engineering benefits:

1. **Interoperability**: A single MCP server works seamlessly across any compatible AI client (Zed, VS Code, Claude Desktop, or custom CLI agents).
2. **Predictable Execution**: Tools return strictly validated JSON schema outputs rather than raw, unpredictable text strings.
3. **Security Auditability**: Security layers inspect and prompt user confirmation for sensitive tool invocations before execution.

As the open-source AI ecosystem continues to grow, standardized context protocols will serve as the foundation for autonomous, multi-agent software engineering.
